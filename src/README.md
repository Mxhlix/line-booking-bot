# Apps Script と LINE への設置

`Code.gs` と `appsscript.json` を、Google スプレッドシートに紐づいた Apps Script プロジェクトに入れて使います。
LINE とつなぐ前に、デモモードで動きを確かめられます。

## デモを動かす

1. Google スプレッドシートを新しく作り、拡張機能 > Apps Script を開きます。
2. 既定のコードを `Code.gs` の中身で置き換えます。`appsscript.json` も同じ内容にします（エディタの設定で「マニフェストを表示」をオンにすると編集できます）。
3. `CONFIG.DEMO_MODE` が `true` のまま、関数 `runDemo` を実行します。初回は権限の許可を求められます。
4. 起きること:
   - 「予約台帳」「設定」「よくある質問」「メニュー」シートができ、架空のサロンの初期値が入ります。
   - 見本の会話（友だち追加、キーワード、予約、同じ枠への2人目の予約、AI の応答、前日リマインド、取り消し）を順に流し、入力と返信を実行ログに書きます。
   - LINE には何も送りません。カレンダーへの登録と削除も、ログに書くだけです。

`runDemo` は最初に「予約台帳」シートを作り直します。実データの入ったシートでは実行しないでください。

## シート

どのシートも、無ければ初回に作って初期値を書き込みます。

| シート | 列 | 中身 |
|---|---|---|
| 予約台帳 | 予約ID / ユーザーID / 予約日 / 開始 / 終了 / メニュー / 人数 / 担当 / 状態 / 受付日時 / リマインド / カレンダーID | Bot が読み書きする予約の記録 |
| 設定 | 項目 / 値 | 店舗名・営業時間・定休日・アクセス・メニュー一覧・電話・クーポン |
| よくある質問 | キーワード（カンマ区切り） / 返信文 | キーワードへの返信。返信文には `{店舗名}` `{営業時間}` `{定休日}` `{アクセス}` `{メニュー一覧}` `{電話}` `{クーポン}` を書くと「設定」シートの値に置き換わります |
| メニュー | ID / メニュー名 / 所要時間(分) / 料金表示 | 予約で選ぶメニュー。所要時間がそのまま予約の長さになります。1件も無ければメニューを聞かず、`CONFIG.BUSINESS.defaultDurationMinutes` の長さで受けます |

シートを書き換えると、次のメッセージから返信に反映されます。

`CONFIG.STORE` と `CONFIG.MENUS` は、シートが無いときに書き込む初期値です。シートができた後は、シートの値を使います。

## 受付のルール

`CONFIG.BUSINESS` で決めます。

| 項目 | デモの値 | 意味 |
|---|---|---|
| openHour / closeHour | 10 / 19 | 受付の開始と終了（時）。終了の時刻までに終わる予約だけを受けます |
| closedWeekday | 2 | 定休日の曜日（0=日、1=月、2=火…） |
| capacityPerSlot | 1 | 同じ時間に重ねて受けられる人数 |
| slotMinutes | 30 | 開始時刻の候補の刻み（分） |
| defaultDurationMinutes | 60 | メニューが無いときの予約の長さ（分） |
| askPartySize | false | `true` にすると人数（1〜4名）を聞きます |
| STAFF | [] | `[{id:'sato', name:'佐藤'}]` のように入れると担当を選ばせ、担当ごとに1件ずつ数えます |

## LINE とつなぐ

1. LINE Developers で Messaging API のチャネルを用意し、チャネルアクセストークンを発行します。
2. Apps Script のプロジェクトの設定 > スクリプト プロパティに、次を入れます。コードには書きません。
   - `LINE_CHANNEL_ACCESS_TOKEN`: チャネルアクセストークン。返信と push に使います。
   - `AI_API_KEY`: 生成AI の API キー。入れないと AI には渡さず、スタッフか電話への案内を返します。
3. `CONFIG.DEMO_MODE` を `false` にします。
4. AI を使うときは、`CONFIG.AI.PROVIDER`（`gemini` か `claude`）と `CONFIG.AI.MODEL` を API キーに合わせます。
5. デプロイ > 新しいデプロイ で、種類を「ウェブアプリ」にしてデプロイします。`appsscript.json` では、実行するユーザーはデプロイした本人、アクセスは全員（匿名を含む）になっています。
6. 発行された `/exec` の URL を、LINE Developers のチャネルの Webhook URL に入れ、Webhook の利用をオンにします。
7. LINE公式アカウントを友だち追加し、「営業時間」や「予約」と送って返信を確かめます。

`appsscript.json` が求める権限は、このスプレッドシート、外部への HTTP 送信、カレンダー、トリガーの4つです。

## 前日リマインド

1. `CONFIG.ADDONS.REMINDER` を `true` にします。何日前に送るかは `CONFIG.REMINDER.daysBefore`（既定は1）です。
2. Apps Script のトリガーで、関数 `sendReminders` を毎日1回動く時間主導のトリガーとして追加します。

`false` のままなら、`sendReminders` を動かしても何も送りません。確定の文面にもリマインドの案内は出ません。

## リッチメニュー

`richMenuJson_()` は、リッチメニューの定義（2500×1686 の画像を3列×2行に分けた6つの領域）を返すだけです。
登録の処理は `Code.gs` に入っていません。Messaging API で別に登録します。
6つの領域は、予約する・メニュー・クーポン・営業時間・アクセス・電話です。

## Webhook の署名

GAS のウェブアプリはリクエストのヘッダを読めないため、`X-Line-Signature` による署名の確認はしていません。
`verifySignature_` はスクリプト プロパティ `LINE_CHANNEL_SECRET` を使って署名を計算しますが、`doPost` からは呼んでいません。
